Rama — architecture & fonctionnement du code

Assistant conversationnel d'accès aux statistiques officielles du Sénégal (ANSD). Ce document explique, de bout en bout, comment le code est organisé, comment une question devient une réponse fiable, et où se trouve chaque responsabilité.

01 Vue d'ensemble

RAMA répond à une question en français par un chiffre officiel, une comparaison, une explication de méthode, ou un lien direct vers le bon document. Le système est hybride : il choisit, pour chaque question, la voie la plus sûre — une base de données pour les chiffres, un moteur documentaire pour les explications, un catalogue pour l'accès aux données.

Quatre composants, une interface unique

Orchestrateur

Aiguille chaque question vers la bonne voie et applique les garde-fous. Cœur du système.

Text-to-SQL

Traduit une question chiffrée en requête SQL sur des données officielles, puis la verbalise en français.

RAG

Retrouve les passages pertinents d'un corpus documentaire et rédige une réponse ancrée dans ces passages.

Accès & liens

Catalogue ANADS (285 études) et base de ressources vérifiées ; chaque réponse cite des liens cliquables.

Principe directeur

Rapide et sûr d'abord, souple ensuite. Les cas fréquents sont traités par des moteurs déterministes (millisecondes, zéro hallucination) ; le LLM n'intervient que là où il apporte vraiment — reformulation, rédaction, longue traîne.

02 Cycle d'une requête

Tout passe par ANSDChatbot.ask(). L'ordre des étapes est délibéré : les filtres les moins coûteux et les plus sûrs d'abord, le routage statistique ensuite. Chaque étape peut court-circuiter les suivantes.

−1
Acte socialCHAT

« salut », « merci », « qui es-tu ? » → réponse directe, sans routage ni effet perroquet.

0a
Normalisation des fautes

Correction typo/orthographe par le LLM — sautée si la question est déjà propre (lexique du domaine), pour rester rapide.

0b
Contextualisation

« Et en 2013 ? » → réécrite en question autonome (substitution d'année/région, ou réécriture LLM).

1
Garde-fou d'entrée

Hors périmètre, injection, question politique/électorale → refus poli.

2
Cache

Réponse identique déjà calculée → servie en ~0 ms.

3
Accès aux donnéesCATALOG

« je veux les données sur X » → fiches ANADS pertinentes + portails (SES, Annuaire, Open Data), en liens directs.

4
NavigationNAV

« où télécharger… » → réponse composée depuis la base de liens vérifiés.

5
Routage statistique

Classifieur → SQL · RAG · HYBRID ; sous le seuil de confiance, le LLM tranche.

6
Exécution de la voie

Génération SQL par gabarits + verbalisation, ou récupération + rédaction ancrée, ou les deux (HYBRID).

7
Garde-fou de sortie (fidélité)

Les chiffres de la réponse doivent être couverts par les preuves citées, sinon la réponse est signalée.

8
Liens cliquables

Ressources officielles et titres d'études ANADS mentionnés deviennent des liens — même dans une réponse rédigée par le LLM.

9
Suggestions + mémoire + journal

3 questions de suivi ancrées dans la réponse, mise en cache, historique de session, télémétrie anonyme.

Chaque responsabilité vit dans un module dédié, testable indépendamment.

core/telemetry.pyObservabilité. Répartition des voies, latence p50/p95/par-voie, taux de refus, satisfaction — données anonymes.
core/config.pyConfiguration. Mode démo/production, fournisseur, clés, CORS, seuils — via variables d'environnement.
api/main.pyServeur HTTP. FastAPI ; /api/chat et flux SSE ; rate-limit, CORS, pages 404/500, service du frontend.

04 Routage à deux niveaux

Contribution centrale du mémoire : f(q) → {SQL, RAG, HYBRID}.

  • Niveau 1 — classifieur léger. En démo, TF-IDF (1–2 grammes, mots + caractères) + régression logistique, reproductible sans GPU. En production, DeBERTa-v3 affiné sur un corpus annoté.
  • Niveau 2 — arbitrage LLM. Quand la confiance du classifieur passe sous 0,85, le LLM tranche. La confusion se concentre sur la classe HYBRID (« chiffre et explication »), sémantique par nature — ce qui justifie empiriquement ce second niveau.
Pourquoi hybride plutôt que « tout LLM »

Un chiffre officiel ne se devine pas : il se lit dans une base. Le routage garantit qu'une question chiffrée part vers SQL (exact, traçable) et non vers une génération libre susceptible d'halluciner.

05 Les voies de réponse

SQL — le chiffre exact

Le schéma ANSD est connu et fermé : les questions usuelles se projettent sur un nombre borné de formes SQL. L'appariement par gabarits est plus rapide et plus sûr qu'une génération LLM sur ce périmètre. La réponse est verbalisée en français à partir des lignes retournées — jamais un chiffre inventé.

Q  « Quelle est la population du Sénégal en 2023 ? »
→  SELECT population FROM population_nationale WHERE annee=2023
→  « Le Sénégal comptait 18 126 390 habitants en 2023 (recensement). »

RAG — l'explication ancrée

Le corpus documentaire (méthodologies, notes, FAQ) est découpé en sections, indexé, puis interrogé. La rédaction s'appuie sur les passages récupérés, qui servent aussi de preuve au rail de fidélité — ce qui évite un double calcul.

CATALOG — l'accès aux données

Une demande d'acquisition (« je veux les données sur la pêche ») est résolue en liens directs : fiches ANADS pertinentes (avec leur URL vérifiée), puis SES, Annuaire statistique et Open Data pour les séries agrégées. Jamais « information non disponible » quand la donnée existe.

NAV — le bon document

« Où télécharger le rapport EHCVM ? » compose sa réponse directement depuis la base de liens vérifiés, sans extraction hasardeuse.

HYBRID — chiffre et explication

Certaines questions veulent les deux : un chiffre et son interprétation. La voie combine SQL et RAG, puis (en production) une synthèse finale par le LLM.

06 Garde-fous & garanties

La fiabilité n'est pas un effet de bord : elle est imposée par le code.

GarantieMécanisme
Aucun chiffre hallucinéLes nombres proviennent verbatim de la base (SQL) ou du catalogue ; grounding structurel.
Aucune URL inventéeTous les liens viennent de resources.json (URL vérifiées) ou des fiches ANADS.
Fidélité vérifiéeRail de sortie : les chiffres d'une réponse RAG doivent être couverts par les passages cités.
Périmètre respectéRail d'entrée : hors-sujet, injection, politique/électoral → refus poli.
Base en lecture seuleSQL exécuté en mode=ro : aucune écriture possible.
Pas de fuiteGestionnaire global : jamais de 500 brut ni de trace ; /api/health n'expose qu'un booléen.
En clair

Quand RAMA ne sait pas, il le dit et oriente vers le document — il n'improvise pas. Chaque affirmation chiffrée est traçable jusqu'à sa source officielle.

07 Stratégie LLM

Le même code fonctionne sans clé (démonstration déterministe) comme avec un fournisseur rapide (qualité rédactionnelle maximale).

  • Multi-fournisseur. Client compatible OpenAI : Groq, DeepSeek, OpenAI, Mistral, OpenRouter, Ollama — changer de modèle = deux variables d'environnement.
  • Dégradation gracieuse. FallbackLLM ne lève jamais : si l'API est injoignable, il bascule sur le moteur local. Le service reste disponible.
  • Mode éclair. Sur un fournisseur lent, toutes les voies utilisent les moteurs déterministes ; le LLM n'est sollicité que sur un fournisseur rapide.
  • Concurrence bornée. Un sémaphore limite les appels distants simultanés — pas de tempête de requêtes, pas de 429 en cascade.

09 Interface web

Une seule page autonome (frontend/index.html), servie par l'API en même origine — aucune dépendance externe (CSP-compatible).

  • Flux en direct. Les réponses arrivent en streaming (SSE) sur un fournisseur rapide ; repli non-flux sinon.
  • Rendu riche. Tableaux, graphes, liens cliquables (ressources et titres d'études), suggestions évolutives.
  • Produit soigné. Identité ANSD (bleu marine, océan, blanc), logo calligraphique, thèmes clair/sombre, PWA installable, accessibilité clavier, page « À propos & confidentialité ».

Avec un fournisseur rapide (Groq), la robustesse aux fautes de frappe passe à 2/2 et la latence p50/p95 à 621 / 3 956 ms (appels LLM inclus). L'évaluation est intégrée en garde-barrière : une régression d'exactitude ou de sécurité fait échouer la CI.

12 Déploiement

Image Docker mono-instance, recherche TF-IDF (sans GPU), frontend servi par l'app.

cp .env.example .env          # renseigner la clé LLM
docker compose up -d --build
curl localhost:8000/api/health

Sécurité de packaging vérifiée : aucun secret dans l'image, exécution en utilisateur non privilégié, sonde de santé, redémarrage automatique. Détail complet et checklist : docs/DEPLOIEMENT.md.
